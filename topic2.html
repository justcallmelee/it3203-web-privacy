Smart Contracts, Security & Privacy Risks

Topic 2: The new threats that come with public, permanent code

What Smart Contracts Do

A smart contract is a program stored on a blockchain such as Ethereum. It holds funds or data and follows fixed rules written in code. When someone sends a transaction that meets those rules, the contract runs automatically, without a bank, lawyer, or company in the middle. Smart contracts power decentralized finance (DeFi), NFT marketplaces, and decentralized applications (dApps).

Security Risks

Because contract code is public, attackers can study it for mistakes. And because it is usually immutable once deployed, a bug cannot simply be patched the way a normal web application can. Common weaknesses include:

  • Reentrancy: a malicious contract calls back into the victim contract before the first call finishes, draining funds.
  • Access-control mistakes: functions that should be restricted to the owner are left open to anyone.
  • Logic and math errors: incorrect calculations that can be exploited for profit.
  • Key theft: if a private key is stolen, the attacker has full control of the account.
  • Phishing and malicious approvals: users are tricked into signing transactions that give away their tokens.
Table 2. Well-known Web 3.0 security incidents
Incident Year Cause Lesson
The DAO 2016 Reentrancy bug in a smart contract Code must be audited before it holds real value
Ronin Bridge 2022 Attackers gained control of validator private keys "Decentralized" systems can still depend on a few keys
Wallet-drainer phishing Ongoing Fake sites ask users to sign harmful approvals Users must understand what they are signing

Privacy Risks of Public Ledgers

Most people assume that a wallet address is anonymous. In reality, it is pseudonymous: the address is not your name, but every action it takes is public and permanent. Blockchain analysis companies and researchers can often link addresses to real people by following the flow of funds.

Ways a user's identity can be exposed:

  1. Buying cryptocurrency on an exchange that requires ID verification (KYC).
  2. Posting a wallet address or ENS name on social media.
  3. Reusing the same address across many applications.
  4. dApp websites that still use ordinary trackers, cookies, and IP logging.
Permanence matters: a privacy leak on a normal website can sometimes be removed. A leak recorded on a public blockchain stays there forever.

Privacy-Enhancing Solutions

Developers are building tools to bring stronger privacy to Web 3.0:

  • Zero-knowledge proofs (ZKPs): prove that something is true (for example, "I have enough funds") without revealing the underlying data.
  • Privacy-focused blockchains: networks such as Zcash and Monero hide transaction details by default or by choice.
  • Selective disclosure credentials: share only the specific facts a service needs.
  • Smart contract audits: independent reviews of code before launch.
  • Hardware wallets: keep private keys offline and away from malware.
Table 3. Privacy benefits and limitations of Web 3.0
Potential Benefit Related Limitation
No email or password needed to sign in Wallet activity can be tracked across sites
No central database to breach All transactions are public by default
Tamper-resistant records Mistakes and personal data cannot be erased
User holds their own keys Lost or stolen keys usually cannot be recovered

Summary

Smart contracts remove the need to trust a middleman, but they ask users to trust code instead. Public blockchains remove central databases, but they make activity visible to everyone. Real privacy in Web 3.0 depends on tools like zero-knowledge proofs, careful security practices, and users who understand the risks.
